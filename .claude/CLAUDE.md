# bob_core

> Auto-generated by /analyze-project on 2026-10-13. Last synced: 2026-10-13.

Shared kit for "Bobs": long-running Claude Code agents, each with one job. Core holds the shared rules, CLIs, hook gates and templates; each Bob is a sibling folder scaffolded from a manifest. Extracted from an earlier production Slack fleet with all company-specific parts removed. Full brief: `~/Downloads/BOB-CONTEXT.md`.

## Rules for working on core
- Keep core domain-free: no company, product, market or subject knowledge. Bob-specific code goes in the Bob's folder (`bobs/<slug>` or a sibling repo); shared behaviour goes in core and must pass `./selftest.sh`
- Never edit `bob_core` from inside a Bob's work
- Every per-Bob value comes from the manifest via `bobcfg`; never hard-code ids, paths or ports
- New state goes under `bobcfg.state_home()`; new evidence goes through `evidence.save`
- Stdlib only. Docstrings explain *why* (the failure a function prevents). Every module gets a `--selftest` or a test suite
- Tests come in refuse/allow pairs. A new check is not done until a deliberate break of the guarded code made it fail; make and revert that break with the editor, not `sed -i`
- Shell: short single-purpose commands; never overwrite files from the shell; stop background processes by PID
- Commit or push only when asked. `fleet.toml` gets local absolute paths from `new_bob.py`: review before committing

## Design principles (keep them)
- Rules -> tools -> guards: a prose rule that keeps breaking becomes a tool; a bypassed tool becomes a hook that refuses
- Evidence or it did not happen: save raw read + query + UTC window; quote, don't paraphrase
- Three verdicts: yes / no / could not tell. "Not found" counts only if the search provably covered place and time. A capped read is a floor, not a count
- Fail open vs closed is deliberate: advisory hooks fail open (a gate that stalls work gets removed); state-protecting gates refuse; ledgers skip torn lines rather than crash
- Append-only ledgers, never overwrite: a duplicate is recoverable, a silent drop is not
- Learning stops at proposals: the agent writes/fixes/retires lessons and may propose a tool or gate, never builds or loosens its own guards without a person's approval
- Authority is explicit: only manifest-named people direct a Bob; credentials are named with an access level, never pasted

## Tech Stack
- Python 3.11+ (needs `tomllib`), stdlib only: no dependencies, no `requirements.txt`, no packaging
- macOS and Windows. Bash for `selftest.sh` and `launch.sh` (Git Bash on Windows)
- Supervisor scheduler: launchd on macOS, Task Scheduler on Windows (`supervisor/tick.cmd`); `new_bob.py` writes the one for the machine it runs on
- Markdown (`CORE.md`, `templates/loops/*.txt`) is "code" too: it steers the agent

## Build & Run
- Test everything: `./selftest.sh` (sets `BOB_MANIFEST=bob.example.toml` and a temp `CLAUDE_CONFIG_DIR`)
- One suite: `BOB_MANIFEST=$PWD/bob.example.toml python3 harness/test_route.py` (plain asserts, prints PASS/FAIL per `test_*` function; no pytest)
- One module: `python3 harness/<module>.py --selftest` (selftest.sh auto-discovers any file containing a `--selftest` arg)
- Validate a manifest: `python3 harness/bobcfg.py` / read one value: `python3 harness/bobcfg.py board.port`
- Scaffold a Bob: `python3 automation/new_bob.py <manifest.toml> --out ../<slug>` (out dir must be new or empty)
- No CI, no linter config, no Docker

## Architecture
- Nothing runs on its own. Three kinds of file: Markdown that steers the agent; CLIs the agent calls via Bash; things run outside the agent (hooks by Claude Code, supervisor by launchd every 20 min)
- Every per-Bob value comes from the manifest via `bobcfg.py`; `bobcfg.get` raises on missing keys by design (no defaults, so one Bob's value never leaks into another)
- Manifest discovery: `$BOB_MANIFEST`, else nearest `bob.toml` above `harness/`, else nearest above cwd. Supports core beside Bobs (`george/bob_core`, `george/tutor`) and core nested inside a Bob
- Required sections `[bob] [board] [loops] [paths]`; optional `[slack] [routing] [runtime] [credentials]` are validated in full when present. Errors are collected and raised together (`ManifestError.errors`)
- Path resolution: `[paths] evidence_dir`/`state_dir` resolve under `data_root` (if set); every other path under the Bob's folder. Paths must be relative and contain no `..`
- Generated Bobs reference core by relative path (`{core}` placeholder = `os.path.relpath`), so Bob and core folders must keep their relative position
- Board (`board_shell.py`): stdlib `ThreadingHTTPServer` + SSE; `[board] panels = ["mod"]` hands the whole board to `mod.main`, built on `BaseHandler` (only one panel module supported)

## External Integrations
- Claude Code CLI: supervisor shells out to `claude` (`agents --json`, resume, rm); `[runtime] claude_bin` needed under launchd's minimal PATH
- Slack: no client in core. The agent uses a Slack MCP plugin; core only lints text (`slack_lint.py`), tracks timestamps/threads from saved reads, and gates sends via hook matcher `mcp__.*[Ss]lack.*__slack_(send_message|send_message_draft|schedule_message)`
- Scheduler: `templates/supervisor/agent.plist` (launchd) or `templates/supervisor/tick.cmd` (Task Scheduler), checked/healed by `watchdog_check.py`
- Credentials: manifest names them with `access` (`read-only`/`read-write`, `why` required for write). `new_bob.py` rejects token-shaped values (`xox*-`, `ghp_`, `AKIA`, `sk-`...). `redact.py` scrubs credentials before evidence is saved

## Configuration Binding
- `bob.toml` (per Bob) -> `bobcfg.config()` (cached per process via `functools.cache`)
- Env: `BOB_MANIFEST` (manifest override), `CLAUDE_CONFIG_DIR` (state home; `launch.sh` sets `~/.claude-<slug>`), `REFLECT_STATE` / `REFLECT_WATCH_DIRS` (reflect_gate overrides)
- `[runtime] env_file`: absolute path to a strict `KEY=value` secrets file outside every repo (`envfile.py` refuses one under the Bob, core or any `.git` tree). `launch.sh` validates it with `envfile.py --path` then reads it line by line (never `source`); `session_supervisor` loads it fail-open before resuming. Existing env vars win. Never Read that file: it holds live keys
- `[runtime] state_subdir`: several Bobs share one config dir/login; state goes to `<config dir>/<state_subdir>` and `launch-shared.sh` is used instead of `launch.sh`
- Template placeholders: `{dotted.manifest.key}` plus computed `{core}`, `{core_abs}`, `{bob_abs}`, `{python}`, `{authority}`, `{channels_line}`, `{directed_by}`, `{report_to}`, `{config_dir}`. An unknown placeholder fails the whole render before anything is written

## Runtime Behavior
- State files live in `bobcfg.state_home()` (config dir, not the Bob folder): `loop-passes.jsonl`, `release-posted.json`, `skill-fires.jsonl`, `skill-gate-state.json`, `slack-mention-seen.txt`, `slack-watch-dm-cursors.json`, `slack-watch-polled.json`, `reflect-gate-state.json`, `watchdog-heals.log`. `test_state_home_wiring.py` enforces this for every module-level path constant
- Module-level constants call `bobcfg.state_home()` at import: importing `loop_passes`, `slack_*`, `release_digest`, `watchdog_check`, `reflect_gate` requires a valid manifest to be findable
- Evidence: `evidence.save()` writes `<evidence_dir>/<UTC date>/<id>/{raw.txt,query.txt,meta.json}`; never overwrites (same id same day is refused); naive timestamps are refused
- `release_digest.py` posts everything above the last posted heading, never by clock
- `new_bob.py` renders all files in memory first, then writes, then appends to `fleet.toml` (uniqueness of slug and port is checked against it)
- Gates: `skill_gate` never denies and fails open (shows a lesson max once/session/hour, 3 per call); `commit_gate` fails open on its own parse errors; `reflect_gate` is opt-in, max 2 blocks per session
- Loop templates: `slack-watch`, `release-digest` (need `[slack]`), `health-checks` (needs `[runtime]`), `lessons-review`. Each loop first re-registers via `CronList`, then `loop_passes.py --record <name>`. A loop's name is its file stem and must have a `[loops.schedules]` entry

## Project-Specific Patterns
- Module shape: module docstring with purpose + `Usage:` block, `from __future__ import annotations`, `sys.path.insert(0, HERE)` then `import bobcfg  # noqa: E402`, `main(argv) -> int`, `raise SystemExit(main(...))`
- Each module that can fail silently has a `--selftest` that proves it still refuses bad input
- Tests: standalone scripts, `test_*` functions with bare `assert`, temp dirs via `tempfile.mkdtemp()`, CLIs driven via `subprocess` with a scrubbed env. Gate tests always cover both directions (must-refuse + must-allow)
- Output conventions: `OK` / `FAIL: ...`, `WATCHDOG: PASS|HEALED|FAIL`; exit code 1 on failure
- Docs voice (README, CORE, docstrings): plain, terse, no em-dashes; explains *why* a rule exists

## Cross-platform (macOS + Windows)
- OS differences live in `harness/oscompat.py`; use it, don't reintroduce the POSIX spellings:
  - `pid_alive(pid)`: never `os.kill(pid, 0)` (on Windows signal 0 is CTRL_C_EVENT: it sends Ctrl+C to that process group)
  - `lock`/`unlock`: never `fcntl` directly (absent on Windows)
  - `toml_str(value)`: any string written into TOML (Windows backslashes are invalid escapes)
  - `posix(path)`: any path rendered into shell commands, `@imports`, or hook commands (Git Bash eats backslashes)
  - `utf8_stdio()`: first line of every `if __name__ == "__main__":` block (Windows pipes default to cp1252: printing "Ł" crashes, UTF-8 on stdin arrives garbled)
- Every text `read_text` / `write_text` / `open` / `subprocess(text=True)` passes `encoding="utf-8"`. `harness/test_text_encoding.py` refuses any that do not (test files excepted); a Bob runs the same `findings()` over its own harness
- `new_bob.py` writes LF everywhere except `*.cmd` (CRLF); `.gitattributes` enforces the same in the repo
- `bobcfg` accepts absolute paths in POSIX or Windows form; relative paths reject `..`, roots and drives in either form
- `watchdog_check.py`: macOS reads `launchctl print`; Windows reads `Get-ScheduledTask` via PowerShell (JSON, locale-independent), heals with `schtasks /Run`
- Not verified live on Windows: an installed supervisor task resuming a real session (`claude agents --json`, `--bg --resume`)
