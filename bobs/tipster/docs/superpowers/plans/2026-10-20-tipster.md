# Tipster v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

## Execution (the person's choice)

- **One agent builds everything.** The session that runs this plan implements every task itself, in order. No subagent writes code.
- **Subagents only verify, and there are two of them**, launched together once Task 16 is committed (before the live round of Task 17), each reviewing the whole build against the spec and this plan:
  1. **With context:** a fork of the building session (`subagent_type: "fork"`), which knows the conversation, the decisions and the deviations made along the way.
  2. **Without context:** a fresh `general-purpose` agent given only the spec path, this plan's path and the commit range (`git log` from the plan commit to HEAD). It must judge the code from the documents alone.
- Each verifier reports findings ranked by severity, each with file, line and a concrete failing case; neither edits files. The building session checks every finding against the code, fixes the confirmed ones with a test that failed first, and records in the tracker what was fixed and what was rejected and why. Then Task 17.

**Goal:** Build `bobs/tipster`, a Bob that finds Euroleague bets with a calibrated team model, has Claude review each one (veto only), records every tip on a model track and a reviewed track in simulated €1,000 wallets, watches tipped games until tip-off, scores them by profit and closing line value, and sends tips and updates to the person on Telegram (one-way).

**Architecture:** A sibling Bob scaffolded by `automation/new_bob.py`, like the Investor and Trader. Scripts compute every number: official Euroleague stats feed ratings, a shrunk ratings-and-pace model with home advantage turns matchups into probabilities, a pricing module finds edges against the better of bet365 and Stoiximan and sizes stakes, and an append-only ledger replays both wallets. Claude's part is the review CLI (keep, halve, veto, with evidence) and reading news. A request budget guards the odds provider's free quota. Telegram sending is a new domain-free core module.

**Tech Stack:** Python 3.11+, standard library only; plain-assert test scripts run through `harness/testkit.py`; Git Bash on the person's Windows PC.

**Spec:** `bobs/tipster/docs/superpowers/specs/2026-10-20-tipster-design.md`

## Global Constraints

- Stdlib only. No new dependencies.
- Every `read_text` / `write_text` / `open` / `subprocess(text=True)` passes `encoding="utf-8"` (`harness/test_utf8_io.py`, Task 1, refuses otherwise).
- Every network read goes through `fetch.read`, so it is saved as evidence before use. `fetch` refuses any host outside `fetch.ALLOWED_HOSTS` (Task 1). **No bookmaker host is ever allowed** (spec 8).
- Never read odds from a bookmaker website; odds come only through the provider chosen in Task 0 (spec 3.1).
- Euroleague stats: at most one request every 250 ms (`stats_per_second = 4`), every response cached, a finished game never refetched (spec 3.2).
- Module shape: docstring with the *why* and a `Usage:` block, `from __future__ import annotations`, `sys.path.insert(0, str(pathlib.Path(__file__).resolve().parent))` then `import tipsterpath  # noqa: E402,F401`, `main(argv) -> int`, `if __name__ == "__main__":` starting with `oscompat.utf8_stdio()`.
- Output convention: `OK ...` or `FAIL: ...`; exit 1 on failure. A refusal inside a run is a ledger line, not a crash.
- Scripts compute every probability, edge, stake, wallet and CLV. Claude never writes one; the review CLI has no argument that could carry one (spec 5).
- Missing data is `None` / "could not tell", never a default, a zero or a carried-over value.
- All times are stored and compared in UTC; Athens time (`Europe/Athens` via `zoneinfo`) is for display only.
- No em-dashes (U+2014) anywhere.
- Tests come in refuse/allow pairs. After each new check passes, break the guarded line once with the editor (never `sed -i`), confirm the named test fails, restore it.
- Never overwrite files from the shell; edits use the editor. Short single-purpose shell commands.
- Work on `main` on the Windows PC (`C:/Users/georg/src/george/bob_core`); never create a branch in this repo. Commit after each task and `git push`. End every commit message with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- Commands run from `bobs/tipster/` unless stated. One suite: `python3 harness/test_<name>.py`. All: `./selftest.sh`.
- `bob.toml` keeps `mode = "off"` in every commit. Only the person switches it on.
- Never Read the env file; it holds live keys. `python3 ../../harness/envfile.py --check` lists key names.

## Review Focus

1. **Final Four games are on a neutral court:** home advantage must be 0 there (Task 5 `test_final_four_has_no_home_advantage`).
2. **A team with no previous Euroleague season** (2026-27 newcomers such as Dubai) gets the league average as its prior, not a crash, a zero or another team's numbers (Task 4 `test_newcomer_prior_is_league_average`).
3. **An odds team name that does not map** to a Euroleague club code drops that game as "could not tell" with the name logged, never a guessed match (Task 7 `test_unmapped_team_name_is_could_not_tell`).
4. **The clock change on 2026-10-25** (Athens moves from UTC+3 to UTC+2): closing snapshots and "game day" come from UTC start times, so a game that evening is snapped 30 minutes before its real start (Task 12 `test_closing_window_across_dst`).
5. **A postponed game:** no closing snapshot at the old time, and the tip is voided by the stated rule, never settled against a later replay as if nothing happened (Task 12 `test_postponed_game_voids_and_skips_closing`).

### Task 5: Matchup model and probabilities

**Files:**
- Create: `harness/model.py`
- Test: `harness/test_model.py`

**Interfaces:**
- Consumes: `ratings.ratings_at`, `ratings.Season.league` (Task 4)
- Produces:
  - Params dict (written by Task 6): `{"home_adv": float, "k": float, "sigma_margin": float, "sigma_total": float, "fitted_on": [seasons]}`
  - `model.expect(home: dict, away: dict, league: dict, params: dict, neutral: bool) -> {"margin": float, "total": float, "pace": float}`:
    pace = pace_h × pace_a / league pace; pts_h = pace × ortg_h × drtg_a / league ortg / 100 (and the same for away); margin = pts_h − pts_a + (0 if neutral else home_adv); total = pts_h + pts_a
  - `model.p_home_win(exp, params) -> float` = P(margin > 0)
  - `model.p_side(exp, params, side: "home" | "away", line: float) -> (p_win, p_push)`: handicap on that side, with a whole-number line's push as P(|margin + line − 0| < 0.5) using the normal with continuity correction
